# Owner JSON publishing draft (not production-ready)

The owner editor is authenticated by `ADMIN_PASSWORD` and `ADMIN_SESSION_SECRET` (see existing login). Publishing stays disabled unless the server has **all** of `GITHUB_CONTENT_TOKEN`, `GITHUB_PUBLISH_BRANCH`, and `GITHUB_PUBLISH_ENABLED=true`. Keep the token in server-side environment only. The branch must be named explicitly; there is no fallback to `main`, and this draft rejects `main` outright until the production branch is approved. The target repository is fixed to `Petrgyure/geeandgeesus-web`. Do not enable this gate until the branch and deployment pipeline have been reviewed.

`GET /api/admin/publish` loads both JSON files from that branch with a checked Git head. The editor uses that snapshot rather than local static JSON for editable state. `POST` requires owner session, same-origin request, JSON body with the head from the snapshot, and strict shape/path/HTML validation. It creates both Git blobs and one tree/commit, then attempts a **non-forced** ref update; a changed head yields a conflict. Blobs/commits created before a rejected ref update are unreachable, not partially published. The API caps request and document sizes and returns no token. File uploads remain disabled.

**Before launch:** Link the Vercel project to the intended Git repository and branch without changing its domain, verify that the recovery branch (not the older public `main`) contains the actual live source, verify token permissions and branch protections, and run a real end-to-end publish/read-back/deployment check under owner approval. This draft does not make the live site update immediately: Next.js imports these JSON files at build time. The current `/api/admin/status` intentionally continues to report `publishingReady: false` until that end-to-end deployment verification is complete. The editor explicitly warns that a Git write is not a confirmed production deployment. Check media paths already exist; no upload endpoint is provided.

Local verification: `node --test tests/*.test.mjs`, `npm run lint`, `npm run build`. The Git operations are exercised with injected fake fetch responses; no test performs a GitHub write. Review the allowlisted HTML fragments (`strong`, `br`) and the inherited owner authentication/origin checks before enabling publishing.
